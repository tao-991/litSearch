# Lit Search — Project Rules (for Claude Code)

Read `SPEC.md` first. It is the single source of truth for requirements and design; if something conflicts with it, ask the user before changing direction.

## Tech stack (version 1)
Python 3.12 · Typer (CLI) · httpx (async) · SQLite (`sqlite3`) · Anthropic SDK · pytest · ruff. Version 1 has no web UI, scheduler or Docker.

## Workflow
- Work in phases per SPEC §11. Before each phase, give the user a short plan; after it, run the acceptance checklist, update the docs and commit.
- Endpoints, fields, limits and model IDs of external APIs come from official docs or real requests; record conclusions in `docs/spike-findings.md`.

## Conventions
- Type annotations; `ruff` and `pytest` must pass; unit tests never touch the real network.
- All tunable parameters go through environment variables or CLI flags, and `.env.example` stays current. Never hard-code model IDs, e-mail addresses or keys. Never commit `.env`, `data/` or `out/`.
- **Links, DOIs, authors and years in reports may only come from fields returned by a data source, never generated by the model.**
- One failing data source must not fail the whole run; every failure is written to `source_runs` and shown in the report.
- Persist every step and support `--resume`; cache LLM results by (input hash, prompt_version, model).
- A `--dry-run` estimate and a confirmation step are required before any real run.
- **Everything committed to the repository is written in English**: docs, code comments and docstrings, CLI messages, commit messages. Chinese translations are optional extras under `docs/zh-CN/`; the English file is authoritative.

## Out of scope
- Bypassing paywalls, scraping publisher sites, simulating logins.
- Introducing Celery / Redis / Postgres / vector stores / web frameworks (unless the user agrees first).
- Frequent or concurrent requests to Google Scholar.
